# 배포 작업: 단계별 추가, 편집, 가이드 (설계)

앞선 단순화(`docs/deploy-simplify.md`)의 입력 항목은 그대로 두고, 화면 구성과 편집 권한을 바꾼다.

## 1. 단계 (한 화면에 한 컨텍스트)

새 배포 작업과 편집 모두 같은 단계 화면을 쓴다. 단계 id와 순서:

| id | 제목 | 내용 | 선택 여부 |
|---|---|---|---|
| `name` | 기본 정보 | 이름 | 필수 |
| `playbook` | 플레이북 | Git 레포(URL, 브랜치, 경로, 키) 또는 기본 플레이북 + 변수 안내 | 필수 |
| `target` | 배포 대상 | 인벤토리 + 그룹 + 서버 미리보기 | 필수 |
| `image` | 이미지 | `이름:버전` 한 줄 + 해석 미리보기 (기본 플레이북이면 필수) | 선택 ("이미지 없이 진행") |
| `env` | 환경 변수 | 없음 / 붙여넣기·파일 / 저장된 것 (편집에서는 "지금 것 유지"가 기본) | 선택 (".env 없이 진행") |
| `access` | 권한과 안전장치 | 편집할 수 있는 그룹·사람 + 자동 배포/운영 보호/동시 실행 잠금/실패 시 되돌리기 | 기본값 있음 |
| `review` | 확인 | 지금까지 정한 내용 요약. 각 줄 옆 "고치기"는 편집 모드에서만 | - |

- 단계 본문은 높이가 고정된 영역(스크롤은 그 안에서)이고, 위에 목차, 아래에 (가이드가 켜졌을 때) 가이드 패널, 맨 아래 버튼 줄.
- **목차**: 단계 번호와 제목이 가로로. 지난 단계는 체크, 지금 단계는 강조, 건너뛴 단계는 "–".
  - **새 배포 작업**: 목차는 진행 상황 표시만. 눌러서 이동할 수 없다(버튼 아님). 이전/다음/건너뛰기 버튼으로만 움직인다.
  - **편집**: 목차는 처음부터 전부 채워진(체크) 상태이고, 누르면 그 단계로 바로 간다. 저장 버튼은 어느 단계에서나 누를 수 있다.
- 버튼 줄: 새 배포 작업은 `취소 · 이전 · (선택 단계면) 건너뛰기 · 다음 / 마지막은 만들기`. 편집은 `취소 · 이전 · 다음 · 저장`.
- 다음으로 넘어갈 때 그 단계만 검사한다(기존 검사 규칙 그대로).

## 2. 가이드: "배포를 도와드릴까요?"

- 배포 작업 화면 머리의 "새 배포 작업" 버튼 옆에 `배포를 도와드릴까요?` 버튼(아이콘 `wand`). 누르면 새 배포 작업을 가이드가 켜진 채로 연다.
- 단계 화면 머리에도 같은 버튼(켜고 끄기). 켜면 단계 본문 아래에 `<JobGuide step={id} />` 패널이 나온다.
- 가이드 내용은 `frontend/src/modals/JobGuide.tsx`가 맡는다. 이 파일은 `export type JobStepId` 와 `export const JOB_STEPS` (id, label) 와 `export function JobGuide({ step, mode }: { step: JobStepId; mode: "new" | "edit" })` 를 내보낸다. 단계 화면은 이 타입과 목록을 그대로 쓴다.

## 3. 편집과 권한

### 누가 편집할 수 있나 `can_edit(member, job)`

1. Owner, Admin: 항상.
2. Viewer: 못 한다.
3. 그 밖(Deployer 등): 작업을 만든 사람(`created_by`), 또는 `editors.members`에 있는 사람, 또는 `editors.groups`의 그룹에 속한 사람.

### 데이터

- jobs에 `editors` JSONB (기본 `{"groups": [], "members": []}`), `created_by` (멤버 email, nullable) 추가. 마이그레이션 필요.
- Job 모양에 `editors: { groups: string[]; members: string[] }`, `createdBy: string | null` 추가.
- `job_view`(GET /jobs, POST/PUT 응답, dashboard)에 `canEdit: boolean` 추가. 보여 주기는 기존 `viewer`(Owner의 X-View-As 미리보기 반영) 기준.

### API

- `POST /api/jobs`: 기존 body + `editors` (선택). `created_by` = 로그인한 멤버.
- `PUT /api/jobs/{id}`: `POST /jobs`와 같은 body + `editors`. 차이:
  - 권한 검사는 **로그인한 멤버** 기준 `can_edit`. 아니면 403 "이 작업을 고칠 권한이 없어요."
  - 이름 중복 검사는 자기 자신 제외.
  - `envMode`에 `"keep"`(기본값) 추가: 환경 변수를 바꾸지 않는다.
  - `envMode: "paste"`이고 작업에 이미 환경 변수 세트가 있으면 그 세트의 **새 버전**으로 저장한다. 비밀값을 덮어쓰는 일이라 sudo가 필요하다(없으면 기존 규칙대로 403 `sudo_required`). 세트가 없으면 만들 때처럼 새로 만든다.
  - 플레이북·이미지 처리(레포 재사용/생성, 이미지 자동 등록)는 만들 때와 같다.
  - 활동 기록: "배포 작업 수정", 바뀐 항목 이름을 나열 (예: `api · canary · 플레이북, 이미지`).
- 편집 화면의 그룹·사람 목록은 기존 `GET /api/groups`, `GET /api/members`를 쓴다.

## 4. 되돌리기 버튼 없애기

- 배포 작업 목록의 "되돌리기" 버튼과 빠른 이동(⌘K)의 "되돌리기" 항목을 없앤다. 이전 버전으로 가고 싶으면 실행 창에서 태그를 고르면 된다.
- 그 자리에 "편집" 버튼(아이콘 `edit`). `canEdit`이 false면 보이지 않는다.
- 실행 창(ConfirmRun)의 rollback 전용 문구/분기는 없앤다. 백엔드 `RunIn.rollback`은 남겨도 된다.
- 작업의 안전장치 "실패 시 되돌리기"(자동 롤백)는 그대로 둔다.
